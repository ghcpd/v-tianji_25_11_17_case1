- lastSync never updated
  - Location: refreshCache(), reconcile()
  - Actual: lastSync was never updated; subsequent refresh decisions are wrong.
  - Fix: Set lastSync = Date.now() in refreshCache() after successful refresh.

- In-place mutation of remote data via reverse()
  - Location: refreshCache()
  - Actual: Using list.reverse() mutates the array returned by fetchRemote() in the caller, altering the original remote array.
  - Impact: Surprising side effects for callers, incorrect ordering if array object reused.

- Deduplication uses substring matching (includes)
  - Location: reconcile() merging
  - Actual: Using `m.id.includes(r.id)` treats 'abc' and 'a' as duplicates; not intended.
  - Impact: Missing/hiding remote or local transactions incorrectly.
  - Fix: Use exact equality (m.id === r.id) and deterministic merge logic.

- Duplicate resolution & ordering not deterministic
  - Location: reconcile() merging
  - Actual: Duplicate resolution used prior order (simple concatenation) without a consistent rule for which source wins.
  - Impact: Not deterministic and inconsistent across calls.
  - Fix: Merge deduplicated transactions using a Map keyed by id; pick the latest by timestamp, and return sorted by timestamp.

  - Location: addLocalTx()
  - Actual: addLocalTx always pushes and can create duplicates with same ID.
